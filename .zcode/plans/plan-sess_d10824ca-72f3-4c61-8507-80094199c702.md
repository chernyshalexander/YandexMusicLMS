Единственное действие — дополнить docs/resume-bug-investigation.md разделом,
фиксирующим итог обсуждения для будущих сессий:

1. **Матрица поведения по demux_backend**: pref влияет только на старт трека с начала
   (ffmpeg → ymf/yma; internal → flc/aac). Любое переоткрытие mp4-трека с середины
   (unpause / power-on resume / seek) — всегда внутренний MP4Demux с пропуском аудио,
   независимо от pref. Не-mp4 кодеки (plain flac, mp3) — Range+offset в обоих случаях.

2. **Время жизни**: демуксер и skip-цель живут на объекте соединения (`${*$sock}`),
   умирают с ним; следующий трек и рестарт с начала — снова через выбранный бэкенд.

3. **Обоснование по нагрузке** (вопрос пользователя о слабых ПК): демуксер не декодирует
   и не перекодирует — только парсинг боксов + memcpy; декодирование на плеере/штатных
   профилях LMS. Главная CPU-статья — AES-расшифровка, она общая для обоих путей
   (aes_backend=rijndael → шифрование в C). ffmpeg-профили, наоборот, перекодируют весь
   трек (FLAC-энкодинг / LAME V0) — это тяжёлый путь. Единственная добавка resume —
   разовый бурст на докачку/расшифровку префикса от нуля.

4. **Решение**: принудительный внутренний демуксер только на resume-соединение —
   одобрено пользователем 2026-09-22.
